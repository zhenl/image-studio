# 架构详细说明

本文描述 image-studio 的整体架构、模块职责与数据流。
分步构建过程见 `docs/step-1~8` 系列文档。

## 一、总体架构

```
┌────────────────────────────────────────────────────┐
│ 前端（原生 HTML/JS 单页，无构建）                    │
│  index.html / app.js / style.css                    │
└──────────────┬─────────────────────────────────────┘
               │ REST（JSON）+ SSE（进度）+ 静态文件
┌──────────────▼─────────────────────────────────────┐
│ Fastify 后端（TypeScript，本项目）                    │
│                                                     │
│  routes/      HTTP 入口（薄层：校验 + 编排）          │
│  ├ generate   /generate /jobs /preview /gallery …   │
│  ├ models     模型列表与选择（object_info）           │
│  └ prompts    提示词库 CRUD                          │
│                                                     │
│  services/    业务编排                               │
│  ├ generation 生成全流程（核心）                      │
│  ├ describe   图像反推提示词                          │
│  ├ calibration 耗时自校准                            │
│  └ refs       参考图预处理（sharp）                   │
│                                                     │
│  workflow/    工作流构建（纯函数）                    │
│  comfy/       ComfyClient（HTTP + WebSocket）        │
│  queue/       串行调度器                             │
│  db/          better-sqlite3 存储                    │
│  events/      EventBus → SSE                        │
│  util/        ids / zip / crc32                     │
└──────────────┬─────────────────────────────────────┘
               │ HTTP（/prompt /history /view /upload /object_info）
               │ WebSocket（/ws?clientId=）
┌──────────────▼─────────────────────────────────────┐
│ ComfyUI 常驻服务（comfy-service，端口 8188）          │
│  模型加载/卸载/缓存 全部由 ComfyUI 管理               │
└─────────────────────────────────────────────────────┘
```

## 二、模块职责与依赖方向

依赖方向严格单向：`routes → services → (workflow | comfy | db) → util`。
`workflow/` 与 `util/` 是纯函数层，不依赖任何 I/O。

| 模块 | 职责 | 关键约束 |
|:---|:---|:---|
| `config.ts` | zod 配置（env > .env > 默认值），派生绝对路径 | `loadConfig(env)` 可注入 |
| `app.ts` | Fastify 工厂：路由注册、静态文件、错误处理 | `buildApp(ctx)` 可注入上下文 |
| `context.ts` | 装配 Store/Bus/Scheduler/引擎/校准器/反推 | 全部可注入（测试核心） |
| `routes/` | zod 校验 → 调 service → JSON/SSE 响应 | 不含业务逻辑 |
| `services/generation.ts` | 生成编排：参数→预处理→工作流→提交→监听→落盘→入库→事件 | 引擎以最小接口注入 |
| `services/describe.ts` | 反推编排：预处理→上传→TextGenerate→轮询取文本 | 同上 |
| `services/calibration.ts` | 耗时自校准：images 表中位数拟合 + TTL 缓存 | 纯依赖 Store |
| `workflow/builder.ts` | 三通道工作流 JSON（txt2img/classic/edit） | 纯函数，点号键接线 |
| `workflow/prompt.ts` | 提示词归一化 `<imageN>`（多写法、防重复包裹） | 纯函数 |
| `comfy/client.ts` | ComfyUI 协议封装（见下） | fetch/WS 工厂注入 |
| `queue/scheduler.ts` | 串行队列：上限、失败继续、取消语义 | worker 注入 |
| `db/store.ts` | 5 张表 + 仓储函数 | 路径注入（临时目录） |
| `events/bus.ts` | 进程内事件总线（SSE 数据源） | — |

## 三、ComfyClient：协议封装

应用端与 ComfyUI 的全部交互收敛在一个类（`src/comfy/client.ts`）：

| 能力 | 端点/通道 |
|:---|:---|
| 健康检查 / 设备信息 | `GET /system_stats` |
| 提交工作流（node_errors 即抛） | `POST /prompt` |
| 结果查询 | `GET /history/{id}` |
| 取图 / 上传参考图 | `GET /view`、`POST /upload/image` |
| 模型列表（object_info 可选值并集） | `GET /object_info/{node}` |
| 进度监听 | `ws://…/ws?clientId=` |

**listen() 的三重收敛保证**（踩坑产物，详见
[调试实录-WS消息全部丢弃](调试实录-WS消息全部丢弃.md)）：

1. WS 事件（`progress` / `execution_success` / `execution_error`）
2. **history 轮询兜底**（3 秒一次）——WS 订阅晚于任务完成、丢帧时收敛
3. 超时定时器

可测试性：`fetchImpl` 与 `wsFactory` 是构造参数，测试用假实现覆盖
全部协议分支（含 isBinary 帧语义）。

## 四、两条数据流

### 生成（异步任务）

```
POST /jobs
  → zod 校验 → store.createJob(queued)
  → scheduler.submit() ── 立即 202 返回（位置）
       └（串行）worker = generation.runJob:
            ① resolve 参考图（dataUrl 解码）
            ② sharp 预处理 → 引擎上传 → refNames
            ③ buildWorkflow（三通道按 ref_mode 路由）
            ④ engine.submit → engine.listen（WS+兜底）
               └ progress 回调: store.updateJob + bus.publish
            ⑤ /view 取图 → 按日落盘 → insertImage
            ⑥ bus.publish(image/done) → store.updateJob(succeeded)

浏览器: EventSource(/jobs/:id/events) ← SSE ← bus.subscribe
```

同步路径 `POST /generate` 复用 `runJob`，外加 `withTimeout` 保护与
手动标记 running（不经调度器）。

### 反推（图生文）

```
POST /describe → sharp 预处理（长边 1024/32 对齐）
  → 上传 → CLIPLoader→LoadImage→TextGenerate→SaveText 工作流
  → 提交 → history 轮询 → outputs[node].text[0] → {text}
```

## 五、存储模型（better-sqlite3）

| 表 | 用途 | 要点 |
|:---|:---|:---|
| jobs | 任务状态机 + 参数快照（params_json） | 大字段（参考图 base64）**不落库** |
| images | 产物元数据 | 图库/详情/复现参数；**耗时校准数据源** |
| prompts | 提示词库（kind: prompt/negative） | use_count 排序 |
| —（文件） | 图片本体 | `DATA_DIR/outputs/日期/`，库存相对路径，整目录可迁移 |

写操作全部毫秒级单行 SQL，同步调用不构成事件循环瓶颈；
WAL 模式；`path` 存相对路径保证可移植。

## 六、静态服务与安全

- `/`、`/app.js`、`/style.css`：前端三文件（MIME 手工映射）
- `/data/*`：产物 + 提示词文本，`path.resolve` 后必须
  `startsWith(root)` 防路径穿越（有专门测试用例）
- `bodyLimit 64MB`：多张 base64 参考图

## 七、测试策略

覆盖率门槛建在 `vitest.config.ts`（lines/statements 90%、branches 85%），
不达标即失败。134 个测试全部依赖注入（假 fetch / 假 WS / 假引擎 /
临时目录数据库），毫秒级、无真实服务依赖：

| 层 | 测试方式 |
|:---|:---|
| 纯函数（workflow/util） | 直接断言（含 zip 逐字节结构校验） |
| services | 假引擎记录调用序列，断言编排顺序与落盘结果 |
| routes | `app.inject()` 走完整 HTTP 栈（含 SSE/静态/越权） |
| ComfyClient | 假 fetch/假 WS 覆盖全部协议分支 |

**教训沉淀**：模拟层必须忠实真实语义（WS 帧的 isBinary 事件曾让
测试全绿而生产全坏，见调试实录）。
