## 一、负面提示词（7bb640b）

参数区提示词下方新增多行输入框，随请求的 `negative_prompt` 下发。

**使用要点**：负面提示词只有引导系数 > 1 时才参与采样（CFG 公式：
cfg=1 时无条件分支权重为 0）。因此滑块拖到 1 时界面显示红色提示
"负面提示词不参与采样……请提高到 3 以上"，input 事件实时联动——
这是从 ComfyUI 编辑器对照实验得出的结论（z-image / turbo 蒸馏
模型固定 CFG=1，负面天然无效）。

## 二、提示词管理（ed7906c）

两类条目：`prompt`（常用提示词）与 `negative`（常用反向提示词）。

**接口**（`src/routes/prompts.ts`）：
- `GET /prompts?kind=&q=` —— 按类别与关键字过滤
- `POST /prompts` `{kind, text}` / `PUT /prompts/:id` / `DELETE /prompts/:id`
- `POST /prompts/:id/use` —— 使用计数 +1，返回最新计数

**设计要点**：点选条目即填入对应输入框并自动计数——"使用次数"
是最朴素的排序信号，高频条目自然浮到前面，无需复杂的收藏体系。

## 三、反向推导提示词（图生文，af9768f）

上传一张图 → 本地 Qwen3-VL 生成文字描述（"这张图能被什么提示词
生成出来"）。是写提示词困难户的入口：先生成描述，改几个词再出图。

**工作流**（`src/services/describe.ts`）：

```
CLIPLoader(qwen_image) ─┐
LoadImage ──────────────┼─► TextGenerate ─► SaveText ─► /history 取 text
VAELoader ──────────────┘（推理参数：sampling_mode=off 贪心解码）
```

**三个实现要点**：
1. **TextGenerate 不是输出节点**——必须挂 `SaveText`，否则 ComfyUI
   直接拒绝整个工作流（输出节点判定）
2. 结果从 `/history` 的 `outputs[node].text[0]` 取，不是图片通道
3. 上传图先预处理：长边限 1024、32 对齐、统一 PNG（复用生成
   通道的图像工具函数）

**接口**：`POST /describe` `{image: dataURL, max_length?}` →
`{text}`。前端在画布/图库的详情弹窗里提供"反推"按钮。

## 四、图库与任务增强

- **图片详情弹窗**：大图 + 完整生成元数据（提示词/尺寸/步数/引导
  系数/种子/耗时）+ 下载/删除/收藏
- **收藏**：`?favorite=1` 过滤，星标切换
- **多选批量**：图库选择模式 → 勾选 → 批量删除（连带文件）/ **zip
  打包下载**（STORE 模式——PNG 已压缩，无需 deflate；zip 构建器
  为零依赖实现，crc32 + local file header + central directory）
- **任务详情**：参数快照 + 产物缩略图 + 批量删除（运行中的取消）
- **任务徽标轮询**：Tab 标题显示排队+运行中数量，3 秒自动刷新

**修复插曲**（`30091e9`）：详情/删除接口曾在浏览器上报
`body cannot be empty when content-type is set to application/json`
——DELETE 请求不能带 JSON 头（Fastify 拒绝空 body）。该陷阱先后
在三个前端踩过，最终成为生态统一约定：**fetch 封装只在有 body 时
设置 Content-Type**。

## 五、采样器可选项（64c652a）

请求 schema 新增 `sampler` 枚举（euler / res_multistep / dpmpp_2m /
dpmpp_2m_sde / heun），文生图与传统重绘通道生效；智能编辑通道
保持官方 euler 约定。前端下拉带说明文案（"res_multistep 新推荐，
低步数表现好"）。

来源：用 ComfyUI 编辑器搭的工作流与代码版对照实验——同一图结构
下 res_multistep 4 步已有可看结果，于是吸收进项目。

## 六、模型预设（80d5c28，详见[模型预设](模型预设.md)）

一套配置带齐三件模型 + 参数约定（步数/引导系数），顶栏下拉一次
切换全部生效；`/object_info` 可见性校验 + `.env` 持久化。

动机：Turbo 蒸馏模型与主力模型的参数约定完全不同（CFG 1 vs 4），
只换模型不改参数 → 出图质量断崖。预设把"模型 + 约定"绑死。

## 七、健壮性防护（eab3cd2 / be506eb）

- **静态服务 git 兜底**：`/app.js` 磁盘缺失时直接 `git show HEAD:
  frontend/app.js` 返回内容（不落盘），页面不白屏；日志告警
- **前端文件完整性回归测试**：每轮全量测试后断言前端三件真实
  文件存在——源于一次真实事故（comic-studio-ts 的测试误删了
  真实 app.js，详见其 docs/文件丢失问题根因.md），四姐妹项目
  全部加了这道防线
- **`FRONTEND_DIR` 可注入**：config 新增该项，测试把前端目录
  指到 `mkdtemp` 临时目录，从根上杜绝测试污染生产文件

## 经验小结

这些增强有一条共同主线：**每一项都由真实使用触发**——用着发现
写提示词难（→提示词库、图生文）、等 2 分钟太慢（→采样器与 turbo
预设）、管理产出低效（→批量操作）、断链白屏刺眼（→兜底与防线）。
功能不超前设计，但在出现第二次同类痛点时一定模式化解决
（如 fetch 封装统一、预设机制、回归测试）。
