# 关键技术说明及实现

本文详述 image-studio 中各项关键技术的原理与实现位置，
可作为二次开发的索引。

## 1. ComfyUI API 格式工作流构建（workflow/builder.ts）

### 原理

ComfyUI 的 `POST /prompt` 接受 API 格式工作流：节点字典
`{ [id]: { class_type, inputs } }`，节点间引用写作 `["节点id", 输出槽位]`。
模型按**文件名**引用（`unet_name` 等），ComfyUI 按
`extra_model_paths.yaml` 解析磁盘位置——应用端不需要知道绝对路径。

### 三通道路由

```
buildWorkflow(params, resolved, refNames, strength)
  ├─ edit + 有参考图   → buildEditRefs（TextEncodeQwenImage21）
  ├─ classic + 有参考图 → buildClassicRef（VAEEncode 回 latent，denoise=强度）
  └─ 其余               → buildTxt2Img（EmptySD3LatentImage）
```

### 点号键陷阱（最重要的实现细节）

`TextEncodeQwenImage21` 的 Autogrow 输入（多参考图）在 API 格式里
**必须用点号键**：

```typescript
refNames.forEach((name, i) => {
  nodes[String(21 + i)] = n("LoadImage", { image: name });
  teInputs[`images.image_${i + 1}`] = [String(21 + i), 0];  // ✅
  // ❌ 嵌套字典 {"images": {...}} 会被 ComfyUI 静默忽略，
  //    参考图接不上，编辑退化为纯文生图
});
```

### 官方采样约定

智能编辑通道（Qwen-Image 2.1）：`CFG=1`、`denoise=1`，latent 用
`TextEncodeQwenImage21` 第三输出（尺寸跟随 image_1）；负面提示词
不参与引导。`resolution=1024` 为参考图像素预算（防 12MP 手机原图
撑爆视觉序列且超出 2K 训练范围劣化质量）。

### 提示词归一化（workflow/prompt.ts 的 normalizeEditPrompt）

`image_1` / `image1` / `第1张` → `<image1>`；已是官方格式的先替换为
占位符再还原，防止二次包裹（`<<image1>>`）；超出参考图数量的引用
保持原样。纯函数，全分支测试。

## 2. WebSocket 进度监听与三重收敛（comfy/client.ts）

### 协议

连接 `ws://<host>/ws?clientId=<id>`，提交工作流时带同一 clientId。
JSON 事件（文本帧）：`progress`（步进）、`executing`（节点切换）、
`executed`（节点完成）、`execution_success` / `execution_error`、
`status`（队列变化）；预览图走二进制帧。

### 帧语义陷阱（生产事故修复，详见调试实录）

`ws` 库的 text 帧同样以 Buffer 交付，**必须用 message 事件第二个参数
`isBinary` 区分**——`Buffer.isBuffer(raw)` 会把全部 JSON 事件当预览图
丢弃（进度永远不动，完成全靠兜底）。Python 的 websocket-client
给 str/bytes 可用类型区分，跨语言移植时最易踩。

### 收敛保证

`listen()` 同时挂三道保险，任一触发即收敛：

1. WS 完成事件（正常路径）
2. history 轮询（3s，`/history` 的 `status.completed`）——覆盖
   "WS 订阅晚于任务完成"与丢帧
3. 超时定时器（引擎侧略早于路由层，保证取消逻辑可执行）

## 3. 参考图预处理（services/refs.ts，sharp）

| 函数 | 规则 | 原因 |
|:---|:---|:---|
| `fitReference` | 长边 ≤1536、32 倍数对齐 | 超范围劣化提示词遵循度 + 采样成本暴涨 |
| `resizeToCanvas` | 第 1 张缩放到输出画布尺寸 | 传统重绘的 latent 尺寸由第 1 张决定 |

反推预处理类似但长边限 1024（视觉塔按块计费）。

## 4. 异步任务与串行调度（queue/scheduler.ts）

- GPU 任务并行没有意义（显存互挤，ComfyUI 侧也串行）→ 单消费串行队列
- **失败继续**：worker 抛错标记 failed 后队列继续，一个坏任务不阻塞
- **取消语义**：排队中→直接出队标记 canceled；运行中→置 cancel 标记，
  由 worker 在检查点（每张图开始前）响应——共享 ComfyUI 下不打断
  进行中的推理（`/interrupt` 会波及其它应用）
- 同步路径（`POST /generate`）不经调度器，手动标记 running + withTimeout

## 5. SSE 进度推送（routes/generate.ts + events/bus.ts）

```
引擎线程回调 ──► bus.publish(jobId, event)
                        │
SSE 路由 bus.subscribe ──┘──► reply.raw.write("event: …\ndata: …\n\n")
```

- 浏览器原生 `EventSource` 自动重连；`done` 后主动 close
- 连接关闭（`req.raw.close`）时退订防监听器泄漏
- **任务已终结的连接**立即补发 done 再结束（重连场景）

## 6. 耗时自校准（services/calibration.ts）

跨设备固定系数没有意义（RTX 2060 与 5090 差 40 倍）。模型：

```
elapsed ≈ k · steps · megapixels · batch + overhead
```

- `k` 取 images 表近 30 条 `elapsed/(steps·MP)` 的**中位数**（抗离群点）
- 30s TTL 缓存（估算面板输入抖动不反复扫表）
- 无样本回退 RTX 2060 参考值并标注 `calibrated: false`
- 实测校准后误差 ~10%，随样本增多收敛

## 7. 图像反推提示词（services/describe.ts）

复用出图工作流自带的 **Qwen3-VL-8B 文本编码器视觉塔**，零额外模型：

```
CLIPLoader(qwen_image, device=default)
  → LoadImage → TextGenerate(贪心解码, max_length≤256) → SaveText
```

- **贪心解码**（`sampling_mode: "off"`）：结构化输出更稳定可复现
- TextGenerate 不是输出节点，**必须挂 SaveText** 否则 ComfyUI 拒绝
- 结果从 `/history` 的 `outputs[node].text[0]` 直接取（不落盘读取）
- device 必须 default（cuda）——显存布局交给 ComfyUI 调度

## 8. 模型管理：object_info 权威列表（routes/models.ts）

`GET /object_info/{UnetLoaderGGUF|CLIPLoader|VAELoader}` 的
`input.required.<字段>[0]` 就是 ComfyUI **实际可见**的文件列表——
共享部署下唯一的权威答案（本地目录扫描可能与 ComfyUI 视图不一致）。

- UNETLoader 会混入 text_encoders/vae 子目录条目，按路径首段剔除
- 选择校验必须在列表内（防拼错文件名静默失败）
- 运行时改配置即时生效（工作流按文件名引用）+ 持久化 .env

## 9. 零依赖 ZIP 打包（util/zip.ts + util/crc32.ts）

批量下载需要 zip，但不引第三方包：手写 **STORE 方式**（不压缩——
PNG 本身已压缩）：

- CRC-32 查表法（标准测试向量验证）
- Local File Header + Central Directory + EOCD 逐字段构造
- 测试逐字节断言结构，并用 Python `zipfile.testzip()` 交叉校验

## 10. 可测试性架构（贯穿全项目）

| 手段 | 位置 |
|:---|:---|
| 配置注入 `loadConfig(env, dotenvPath)` | config.ts |
| 应用工厂 `buildApp(ctx)` + `app.inject()` | app.ts / routes 测试 |
| 引擎最小接口（EngineLike/DescribeEngineLike） | services |
| fetch / WS 工厂构造注入 | comfy/client.ts |
| 数据库临时目录 + envFileAbs 指向临时文件 | db / models 测试 |
| sleep 可注入（轮询测试零等待） | describe.ts |

原则：**副作用集中在边界**（I/O、时钟、随机数），业务逻辑全部
可通过注入隔离。这是 134 个测试毫秒级跑完、覆盖率 97% 的基础。
