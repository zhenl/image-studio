# 开发步骤总览：从零到发布的八个阶段

> 本文是开发过程的全景导读。每个阶段的细节在对应的
> `step-N-*.md` 文档（配合同名 git 分支，可 checkout 查看当时
> 的完整代码），本文回答"为什么这样分阶段、每阶段解决什么问题、
> 遇到了什么坑"。

## 开发方法

- **SDD（规约先行）**：动手前先写规约说明，明确边界与验收标准
- **TDD + 覆盖率门槛**：vitest，每阶段结束覆盖率不低于 90%
  （当前 97.2%），全量假实现——测试不依赖真实 ComfyUI，毫秒级跑完
- **小步提交**：每阶段独立分支 + 过程文档，可随时回退或对照
- **真实联调收尾**：单元测试全绿后，跑一次真实 GPU 出图作为
  最终验收（测试通过 ≠ 能出图，见调试实录）

## 八个阶段一览

```
1 骨架 → 2 ComfyUI客户端 → 3 工作流构建 → 4 队列与存储
      → 5 生成服务 → 6 REST API → 7 前端 → 8 模型管理
   依赖方向：下层不依赖上层，逐层向上装配
```

### 第 1 步 · 项目骨架（分支 `step-1-scaffold`）

**目标**：让"空应用"跑起来——Fastify 应用工厂、zod 配置、
健康检查、静态文件骨架。

**关键决策**：
- `buildApp()` 工厂而非全局 app 实例——测试用 `app.inject()`
  内存内请求，不起端口
- 配置经 zod schema + dotenv 可注入（`loadConfig(env)`），
  全局单例配置是测试隔离的天敌

### 第 2 步 · ComfyUI 客户端（分支 `step-2-comfy-client`）

**目标**：封装与 ComfyUI 的全部通信：`submit` / `history` /
`view` / `uploadImage` / `listen`（WebSocket）/ `object_info`。

**关键决策**：
- HTTP 用 `fetch` 工厂注入、WS 用引擎注入——测试传假实现，
  生产传真实现，同一套代码两条路径
- **WS 监听三重收敛**（进度事件 / 终态事件 / history 轮询兜底），
  因为 WS 订阅晚于任务完成时会丢事件

**最大的坑**（记录于[调试实录](调试实录-WS消息全部丢弃.md)）：
`ws` 库的文本帧到达时是 Buffer，判断二进制必须用回调的
`isBinary` 第二参数——用 `Buffer.isBuffer(raw)` 判断曾让
**测试全绿、生产全坏**（所有事件被静默丢弃）。教训：模拟层必须
忠实真实语义。

### 第 3 步 · 工作流构建器（分支 `step-3-workflow`）

**目标**：把三种通道（txt2img / 传统重绘 classic / 参考图编辑 edit）
的 ComfyUI 工作流写成纯函数。

**关键决策**：
- 纯函数 + 类型化参数（`buildTxt2Img(p): Workflow`）——可直接
  单测断言每个节点的 inputs，不碰网络
- 官方约定固化在代码里：编辑通道 CFG=1、denoise=1、点号键
  `images.image_N` 挂多参考图（2~9 张循环接线）

### 第 4 步 · 队列与存储（分支 `step-4-queue-db`）

**目标**：串行任务队列（GPU 一次干一件事）+ SQLite 持久化
（jobs / images 两张表，WAL 模式）。

**关键决策**：
- 队列与业务解耦：调度器只管排队/取消/恢复，worker 回调由
  上层注入
- 存储路径全部可注入，测试跑在 `mkdtemp` 临时目录

### 第 5 步 · 生成服务（分支 `step-5-generation`）

**目标**：编排一次生成的完整生命周期——构建工作流 → 提交 →
监听（进度映射到 2%~98%）→ 取图落盘 → 元数据入库 → 事件广播。

**关键决策**：
- 批量生成种子 `+index` 递增，单张失败不拖垮整批
- 本机耗时自校准（Calibrator）：按近期出图记录拟合，前端
  估算条越用越准

### 第 6 步 · REST API（分支 `step-6-api`）

**目标**：对外的 HTTP 契约——同步/异步生成、任务查询、SSE
进度流、估算、图库、状态。

**关键决策**：
- 同步路径手动标记 running 再执行（不走队列），异步走队列
- SSE 对已完成任务补发 done 事件（前端刷新页面也能立即收敛）
- 已知陷阱：无 body 的请求（DELETE）不能带 `Content-Type:
  application/json`，Fastify 会拒绝空 body——吃过三次亏后
  成为全家的约定

### 第 7 步 · 前端界面（分支 `step-7-frontend`）

**目标**：原生 HTML/JS 单页（无构建步骤）：参数区、画布、
图库、任务四块。

**关键决策**：
- 不引框架——这个体量的工具页，原生 JS + 一个 style.css
  足够，还免了构建链
- 画布大图 + 底部缩略图条，多张批次点击切换
- 估算/警告随输入实时联动（debounce 260ms）

### 第 8 步 · 模型管理（分支 `step-8-model-mgmt`）

**目标**：运行时切换模型三件（扩散模型/文本编码器/VAE），
`/object_info` 是可见性的权威数据源；后续扩展为
[模型预设](模型预设.md)（一套配置带齐模型 + 参数约定）。

**关键决策**：
- 切换前先校验 ComfyUI 可见性，缺文件 4xx 明确报错——
  防拼错文件名静默失败
- 写回 `.env` 持久化，重启后保持

## 发布后的增强（master 直进）

| 增强 | 动机 |
|:---|:---|
| 采样器可选 + CFG=1 负面不生效提示 | 来自 ComfyUI 编辑器对照实验的结论吸收 |
| 模型预设（主力 / Turbo） | Turbo 蒸馏模型参数约定不同，只换模型不改参数会质量崩坏 |
| 图库/任务批量操作、zip 打包下载 | 使用效率 |
| 静态服务 git 兜底、前端文件完整性回归测试 | 历史事故（测试误删真实 app.js）的防线，见 comic-studio-ts 的根因报告 |
