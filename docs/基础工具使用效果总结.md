# Image Studio 作为基础工具的使用效果总结

> image-studio 在本生态里扮演双重角色：它自身是图片生成器，同时也是
> **整个 AI 应用工地的"材料车间"与"试验台"**——试衣间的素材、连环画
> 的测试图、工作流的参数调优都在这里完成。本文用实际数据盘点这些
> 基础工具用途，供后来者参考"为什么要先建一个这样的通用工具"。

## 一、样例图生产：为下游应用造素材

### 试衣间（tryon-studio-ts）的人物与服装库

试衣功能需要"标准素材"：白底全身人物照、平铺服装图。这些不是网上
找的，全部由 image-studio 文生图产出，再通过试衣间的"常用人物 /
我的衣橱"入库：

- 人物照：提示词固化为"全身像、白背景、自然站姿、无遮挡"——
  保证编辑通道参考图质量稳定
- 服装图：生成后直接成为换装测试的 `<image2>` 参考图
- 同一人物配多套服装、同一服装配多个人物的**矩阵测试**素材，
  都是批量生成 + 固定种子复现

### 连环画（comic-studio-ts）的角色立绘与场景概念图

连环画测试期需要的素材类型更多：

| 素材 | 用途 | 在 image-studio 的产出方式 |
|:---|:---|:---|
| 角色白底立绘 | 分镜一致性的 `<image_N>` 参考 | 文生图 + "白底全身"提示词模板 |
| 场景无人物概念图 | 分镜画布参考 | 文生图 + "无人物环境"约束 |
| 测试场景图 | 验证编辑通道多参考融合（2~9 张） | 批量出图后直接进 E2E 测试 |

连环画仓库里 19 张立绘 + 25 张概念图的种子与提示词，最初都在
image-studio 里调通后才固化成 comic-studio 的 `buildPanelPrompt`
模板——**先在试验台调好，再写进生产代码**，避免了"在业务代码里
盲调提示词"的低效循环。

### 模型评测基准图

z-image-turbo 与 Qwen-Image-2.1-Turbo 引入时的对照评测（同种子
同提示词出图对比、速度实测、编辑通道能力验证），全部经 image-studio
的 API 完成——它成了**模型选型的基准测试台**，评测结论直接决定了
预设机制的参数约定。

## 二、提示词调试：从试验到固化

### 有效性验证的工作流

```
image-studio 起草提示词 → 出图肉眼比对 → 调整措辞/权重 → 满意后
  ├─ 存入提示词库（use_count 开始累计）
  └─ 固化到下游应用的代码/模板
```

实际案例：连环画的画风提示词（"水墨漫画风格、毛笔笔触、留白"）
在 image-studio 迭代了十几版，最终固化为 comic-studio 的
`style` 前缀模板；试衣间的换装指令模板（"为 image1 中的人物穿上
image2 中的……其余保持不变"）同样如此。

### 反向提示词的"图生文"入口

写不出提示词时反过来：上传风格参考图 → `POST /describe` 图生文 →
得到文字描述 → 改几个词再生成。提示词库中最常用的条目之一
（英文人像场景描述）就来自这条路径。

### 负面提示词的边界实测

在 image-studio 里实测确认：引导系数=1 时负面提示词完全无效
（CFG 公式决定），这一结论直接变成了界面提示与文档，又反过来
指导了 turbo 模型预设"固定 CFG=1、不设负面输入"的设计。

## 三、同类的其它基础工具用途

1. **工作流参数试验台**：采样器对照（euler vs res_multistep 低步数
   表现）、shift 微调、尺寸/步数与耗时的关系——调优结论直接吸收
   进生成服务（Calibrator 的耗时模型就用这里的出图记录拟合）
2. **ComfyUI 通道验证**：多参考图编辑通道（点号键接线）初次打通、
   WS 三重收敛的验证，都是在 image-studio 的调试实录里完成的，
   之后才被 tryon/comic 复用
3. **E2E 测试图床**：下游应用的端到端测试需要确定性素材——固定
   种子 + 固定提示词在 image-studio 生成一次，产物进测试夹具
4. **新模型快速试跑**：新模型文件放进映射目录后，先在 image-studio
   手动出两张图确认可用性，再考虑做预设接入
5. **素材格式加工**：sharp 预处理（32 对齐、长边限制、PNG 统一）
   生成的标准素材，比手工处理更一致

## 四、使用数据（截至 2026-11-16）

| 指标 | 值 |
|:---|:---|
| 图库累计 | 36 张（txt2img 33 / img2img 3） |
| 生成总耗时 | 约 0.6 小时 GPU 时间 |
| 提示词库 | 5 条（prompt 3 / negative 2），最高使用 2 次 |
| 素材外溢 | 试衣间 12 张、连环画 44+ 张测试素材 |

注：图库计数不含每日清理前的历史批次；外溢素材是关键——
**image-studio 自己的图库不大，但下游应用的素材几乎全部源出于此**。

## 五、经验：为什么生态里第一个 TS 应用应该是通用工具

1. **调试回路最短**：改提示词 → 15 秒出图（turbo 预设）→ 肉眼
   判断，没有任何业务层阻隔
2. **能力沉淀被复用**：ComfyClient、工作流约定、参数校验先在
   这里成型，三个下游项目直接复制模块，省去重复踩坑
3. **接口契约成为生态标准**：生成/任务/图库的 API 形状被
   tryon/comic/z-image-turbo-studio 沿用，前端逻辑近乎移植
4. **试验与生产分离**：参数试验的混乱留在工具里，只有验证过的
   结论进入业务代码——业务仓库的提示词模板全部"有据可查"
